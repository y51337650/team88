# 🏥 디지털 헬스케어 프로그래밍 160시간 마스터 템플릿

> **과정명:** 융합 데이터 기반 차세대 디지털 헬스케어 AI 솔루션 (기초 프로그래밍 160시간 트랙)  
> **훈련 기간:** 1개월 (4주 / 20일 / 1일 8시간)  
> **훈련 방식:** 4~5인 1조 팀 프로젝트 및 2인 1조 페어 프로그래밍(Driver / Navigator)

---

## 1. 저장소 구축 목적
본 저장소는 단순 프롬프트 의존형 코딩(**바이브 코딩**)을 방지하고, 의료 데이터 생애주기(수집 → 비식별화·전처리 → DB 적재 → 통계 검정 → 웹 서비스 배포) 전 과정을 체계적으로 관리하기 위해 설계된 **표준 프로젝트 템플릿**입니다.

1. **의료 데이터 보안 및 규제 준수:** `.gitignore`와 자동화 검사(CI)를 통해 환자 개인식별정보(PII), 원시 의료 데이터(`.csv`), API 인증키(`.env`)가 외부에 유출되는 것을 원천 차단합니다.
2. **투명한 페어 프로그래밍 및 기여도 증명:** 브랜치 분리와 Pull Request(PR) 기반 코드 리뷰를 강제하여 모든 팀원의 논리 이해도와 실제 코드 기여 이력을 기록합니다.
3. **엔지니어링 포트폴리오 자산화:** 매일 작성하는 일일 회고록(`docs/daily_log.md`)과 기술 명세서(`docs/architecture.md`)를 누적하여 취업 시 즉시 활용 가능한 실무형 프로젝트 저장소를 완성합니다.

## 2. 프로젝트 디렉토리 구조 및 역할 설명

```text
AI-class/
├── .github/                          # GitHub 협업 규칙 및 자동 채점/보안 검증 설정
│   ├── PULL_REQUEST_TEMPLATE.md      # PR 생성 시 작성자 로직 설명 및 페어 리뷰 체크리스트
│   └── workflows/
│       └── daily_check.yml           # Push/PR 시 민감 데이터 유출 여부 및 일일 회고록 자동 검사(CI)
├── data/                             # 데이터 저장소 (원시/정제 데이터는 .gitignore로 Git 업로드 차단)
│   ├── raw/                          # 공공데이터 Open API 및 웹 크롤링으로 수집한 원본 데이터
│   └── processed/                    # 결측치 처리 및 개인정보 비식별화가 완료된 분석용 데이터
├── docs/                             # 프로젝트 설계 문서 및 일일 학습 기록
│   ├── architecture.md               # 전체 데이터 파이프라인 아키텍처 및 DB ERD 설계서
│   └── daily_log.md                  # 매일 17:30 작성하는 학습 원리 요약 및 트러블슈팅 회고록
├── notebooks/                        # Google Colab 기반 주차별 탐색 및 실습 노트북 (.ipynb)
├── src/                              # 재사용 가능한 핵심 파이썬 모듈 (.py)
├── app/                              # 4주차 Streamlit 웹 대시보드 애플리케이션 코드
├── .gitignore                        # 환자 데이터(*.csv), 비밀키(.env), 캐시 파일 Git 추적 제외 규칙
├── requirements.txt                  # 개발환경(healthcare_env) 재현을 위한 필수 패키지 목록
└── README.md                         # 프로젝트 개요, 폴더 구조 설명, 팀 R&R 및 협업 규칙 안내
```

## 4. 바이브 코딩 방지 및 협업 규칙
1. **브랜치 보호 원칙:** `main` 브랜치에 직접 푸시하지 않으며, 반드시 `feature/기능명-이름` 브랜치에서 작업 후 페어 파트너의 코드 리뷰(Approve)를 거쳐 병합합니다.
2. **페어 프로그래밍 교대:** 매일 오후 실습 시간 1시간 단위로 **Driver(코더)**와 **Navigator(로직 리뷰어)** 역할을 교대합니다.
3. **일일 회고 의무화:** 매일 퇴실 전(17:30~18:00) 당일 구현한 코드의 작동 원리와 트러블슈팅 과정을 `docs/daily_log.md`에 **150자 이상** 직접 서술하여 커밋합니다.
